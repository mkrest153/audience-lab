편집국 기획 검토 도구

기사로 쓰기 전에,
문장마다 근거를 붙입니다

Audience Lab은 기획과 초안의 문장을 정부·지자체 공개 자료와 대조합니다. 근거가 있는 문장, 출처끼리 설명이 다른 문장, 근거와 어긋나는 문장을 나누고, 아직 모르는 것은 취재 과제로 넘깁니다. 게재 판단은 사람이 합니다.

시연 계정으로 써 보기 도입 문의

가입 없이 시연 계정으로 들어갈 수 있습니다. 시연 공간은 가상의 청람시 자료로 동작합니다.

01 — 왜 필요한가

확인은 늘 마감 직전, 사람의 기억에 기대어 합니다

보도자료의 숫자가 그대로 기사가 됩니다

기관의 설명과 계약대장의 기록이 다를 때, 누가 언제 어느 원문으로 확인했는지가 남지 않습니다.

"12건 모두 공개경쟁" ↔ 대장: 공개경쟁 11건, 긴급 수의계약 1건

범위가 다른 숫자끼리 비교합니다

가구비가 섞인 합계와 공사비만의 금액을 비교하면 같은 사실에서도 결론이 달라집니다.

합계 15억 → 12억: 20% 감소 · 같은 범위 12.5억 → 12억: 4% 감소

더 취재할 것이 기록되지 않습니다

확인하지 못한 인과와 공백이 회의에서 말로만 오가다 사라지고, 기사에는 단정만 남습니다.

"경쟁 확대 덕분에" — 인과 근거는 아직 없음

02 — 하는 일

초안을 넣으면 근거, 상충, 공백, 다음 취재가 한 화면에 정리됩니다

질문만 넣어도, 확보한 공개 원문만 넣어도 됩니다. 아래 화면은 모두 실제 서비스의 시연 공간에서 찍었습니다.

초안 검토 · 교열 대장

문장마다 판정과 권고, 이어지는 질문

초안을 문장으로 나눠 사실·인과·의견을 가르고, 문장마다 근거 있음·상충·반박됨·근거 부족·사실 판정 대상 아님 가운데 하나로 판정합니다.

  • 수치 문장은 서버가 원 단위 정수로 다시 계산합니다
  • 인과 문장은 인과 근거가 따로 있는지 나눠 봅니다
  • 의견·질문 문장은 사실 판정을 하지 않습니다

원문 추적

모든 판정은 원문의 글자 위치까지 이어집니다

판정 → 근거 진술 → 원문 구간 → 원문 버전 → 출처. 모델이 인용한 문장은 서버가 원문에서 다시 찾고, 찾지 못하면 근거로 쓰지 않습니다. 금액은 그 구간에 실제로 적힌 것만 남깁니다.

  • 원문 버전마다 SHA-256으로 고정합니다
  • 같은 계열 출처의 재게시는 독립 확인으로 세지 않습니다
  • 권리가 확인되지 않은 자료는 제목과 주소만 남기고 근거에서 뺍니다

근거 판

말할 수 있는 것, 서로 다른 것, 아직 모르는 것

기준 시각까지 모은 자료를 세 갈래로 정리합니다. 서로 다른 설명은 어느 쪽이 맞는지 정하지 않고 상충으로 남기며, 공백에는 왜 중요한지와 필요한 자료, 확인 방법을 붙입니다.

취재 과제 · 재검토

과제를 끝낸 것과 질문이 풀린 것을 따로 봅니다

판정에서 바로 취재 과제를 만들고 담당자를 정합니다. 확보한 원문을 등록해 다시 검토하면, 질문 상태는 과제 완료가 아니라 새 근거로만 바뀝니다.

  • 정부·지자체 사이트 주소를 넣으면 원문을 서버가 받아 채웁니다
  • 재검토 기준 시각 이후에 받은 자료는 그 재검토에 넣지 않습니다

검토 비교

무엇이 왜 바뀌었는지, 이전 결과는 그대로

같은 초안의 이전 검토와 새 검토를 문장별로 맞대어 판정·근거·권고 가운데 무엇이 바뀌었는지와 그 이유를 보여 줍니다. 더 늦게 만든 결과라고 더 정확하다고 보지 않습니다.

보고서

고정된 검토 기록을 PDF·DOCX·JSON으로

보고서는 고른 검토와 기준 시각, 입력 버전에 고정됩니다. 서버는 파일을 만든 뒤 다시 읽어 형식과 해시를 확인하고, 내려받을 때 브라우저도 크기와 SHA-256을 한 번 더 맞춰 봅니다. 권리가 회수된 자료가 들어 있으면 파일을 내주지 않습니다.

03 — 흐름

질문 하나에서 보고서까지, 다섯 단계

  1. 기획 입력

    기획 질문과 초안(또는 확보한 공개 원문), 기준 시각을 넣습니다. 입력은 버전으로 남습니다.

    기자 · PD · 작가

  2. 공개 자료 수집

    go.kr · korea.kr · kosis.kr에서 자료를 찾고, 서버가 원문을 직접 받아 저장합니다. 관련 보도는 링크만 남깁니다.

    자동

  3. 근거 정리

    원문에서 인용한 문장만 근거 진술이 됩니다. 상충과 공백, 질문 트리를 만들고 상위 질문의 상태는 서버가 다시 계산합니다.

    자동 · 서버 검증

  4. 초안 대조

    문장별 판정과 권고, 필요한 근거를 냅니다. 수치는 다시 계산하고, 판정이 근거 목록과 맞지 않으면 저장하지 않습니다.

    자동 · 서버 검증

  5. 취재와 재검토

    과제를 만들고 새 자료를 등록해 다시 검토합니다. 비교 화면에서 바뀐 점을 확인하고 보고서를 고정해 공유합니다.

    기자 · 데스크

04 — 원칙

하지 않는 것을 먼저 정했습니다

검토 도구가 판단을 대신하는 순간 편집국의 책임이 흐려집니다. Audience Lab은 판단의 재료와 그 출처를 정리하는 데서 멈춥니다.

독자 반응을 예측하지 않습니다

이 기사가 어떤 반응을 얻을지 점치지 않습니다. 대신 받을 수 있는 반론의 틀을 보여 줍니다.

NOT_AUDIENCE_PREDICTION

합성 반론은 사실이 아닙니다

반론 틀은 근거를 다르게 읽는 방식에 대한 합성 해석이라고 화면과 보고서에 표시합니다.

SYNTHETIC_INTERPRETATION · NOT_FACT

점수는 확률이 아닙니다

중요도·검증 가능성 같은 요인은 무엇을 먼저 볼지 정하는 데만 쓰고, 맞을 확률로 쓰지 않습니다.

DECISION_FIRST

권리를 확인한 본문만 저장합니다

정부·지자체 공공저작물(저작권법 제24조의2)만 전문을 저장합니다. 권리가 확인되지 않은 자료는 제목과 주소만 남깁니다.

SOURCE_RIGHTS_EXCLUDED

기준 시각에 고정합니다

판정은 그 시각까지 확인한 자료 범위에서만 유효합니다. 나중에 들어온 자료는 새 검토로 따로 남습니다.

as_of

게재 판단은 사람이 합니다

근거 있음은 게재 승인이 아닙니다. 원문 구간을 열어 직접 확인하도록 모든 판정에 경로를 붙입니다.

HUMAN_DECISION_REQUIRED

05 — 쓰는 사람

기획을 쓰는 사람과 받는 사람이 같은 근거를 봅니다

기자

  • 데스크에 넘기기 전에 문장별로 근거를 점검
  • 숫자 문장의 비교 범위와 계산을 확인
  • 확보한 공개 원문을 등록하고 다시 검토

데스크

  • 근거·상충·공백을 한 화면에서 보고 판단
  • 남은 질문을 취재 과제로 배정하고 진행 확인
  • 고정된 보고서로 검토 이력을 남김

PD · 작가

  • 기획 단계에서 사실관계와 쟁점을 정리
  • 섭외·인터뷰 전에 확인할 질문 목록 확보
  • 초안 없이 질문만으로도 근거 판과 Brief 작성

시연 공간은 편집국 공간과 분리되어 있고, 가상의 청람시 도서관 계약 자료로 입력부터 보고서까지 모든 화면을 써 볼 수 있습니다. 실제 공개 자료 검색과 모델 판정은 관리자가 발급한 편집국 계정에서 동작합니다.

07 — 자주 묻는 질문

도입 전에 많이 묻는 것

어떤 자료를 찾아 대조하나요?

정부·지자체 공개 자료(go.kr, korea.kr, kosis.kr)를 검색해 서버가 원문을 직접 받아 대조합니다. 이미 확보한 공개 원문은 붙여 넣거나, 정부·지자체 사이트 주소를 넣어 가져올 수 있습니다. 관련 보도는 권리가 확인되지 않아 링크만 보여 주고 근거로 쓰지 않습니다.

판정을 그대로 믿어도 되나요?

그렇게 쓰도록 만들지 않았습니다. 판정은 기준 시각까지 확인한 자료 범위 안에서만 유효하고, 근거 있음은 게재 승인이 아닙니다. 모든 판정에 근거 진술과 원문 구간을 붙여 사람이 직접 열어 보고 판단하게 합니다.

AI는 어디까지 하고, 무엇을 서버가 직접 확인하나요?

모델(OpenAI GPT 계열)은 원문에서 인용할 문장을 고르고, 상충·공백을 정리하고, 초안 문장의 판정을 제안합니다. 인용이 원문에 실제로 있는지, 금액이 그 구간에 적혀 있는지, 증감률 계산, 상위 질문 상태 집계, 판정과 근거 목록의 일치, 자료 권리는 서버가 규칙으로 다시 확인합니다. 맞지 않으면 저장하지 않습니다.

입력한 초안은 어디로 가나요?

서비스 서버의 데이터베이스에 저장되고, 검토할 때 문장과 근거 원문이 OpenAI API로 전송됩니다. API 요청은 응답 보관(store)을 끈 상태로 보냅니다. 서비스는 공개 자료만 받도록 설계되어 있으니, 미공개 취재원 정보나 기밀 자료는 넣지 마세요.

독자나 시청자의 반응도 알려 주나요?

알려 주지 않습니다. 받을 수 있는 반론의 틀은 보여 주지만, 이는 근거를 다르게 읽는 방식에 대한 합성 해석이며 사실이나 반응 예측이 아니라고 표시합니다.

계정과 권한은 어떻게 나뉘나요?

공개 가입은 없고 편집국 관리자가 계정을 발급합니다. 열람(읽기), 편집(검토·과제·결과·보고서), 관리(계정 관리까지) 세 가지 권한이 있고, 권한은 서버가 확인합니다.
